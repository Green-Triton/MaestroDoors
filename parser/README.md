# maestro-parser

Извлекает из `Каталог MaestroDoors ИЮЛЬ.pdf` два артефакта: изображения дверей
и структурированный датасет характеристик.

```bash
python run.py                    # полный прогон, пути по умолчанию
python run.py --pdf other.pdf    # другой каталог
python run.py --keep             # не очищать папку с изображениями
python run.py --quiet            # без построчного вывода
```

Результат:

```
frontend/public/doors/*.webp                      205 файлов
frontend/src/shared/api/catalog/doors.data.json   датасет
```

## Что видит парсер

Каталог свёрстан в CorelDRAW по жёсткой сетке, и это единственная причина,
по которой его вообще можно разобрать автоматически:

- страницы 2–28 — товарные, 1 и 29 — обложки;
- на странице до **двух дверей**, одна под другой;
- у каждой двери **два вида**: снаружи (слева, с коробом) и внутри (справа);
- справа от них — колонка характеристик в формате `Метка: значение`;
- заголовок — 14 pt полужирный, цвет `#5b5b5b`; статусы — тот же кегль, `#434242`;
- тело характеристик — 9 pt.

Всё это описано константами в [`config.py`](maestro_parser/config.py).

## Почему нельзя просто выгрузить картинки

Наивный обход `page.get_images()` с сохранением каждого XObject даёт мусор —
именно так выглядела первая попытка. Причины:

1. **Двери составные.** Остекление, зеркала, ручки, броненакладки и 3D-панели
   лежат отдельными изображениями поверх полотна. Выгрузив только базовую
   картинку, получаешь дверь с дырой на месте стекла.
2. **Прозрачность лежит отдельно.** Большинство видов — это JPEG плюс soft-маска
   отдельным объектом. Слепая выгрузка кладёт рядом с полотнами кучу
   чёрно-белых масок.
3. **Кадрирование разное.** Вид снаружи снят с коробом и наличником, вид
   внутри — без них. Если сохранять сырые bounding box'ы, дверь меняет размер
   при переключении вида.

Плюс CorelDRAW оставляет за пределами листа неиспользованную графику
(встречаются прямоугольники с `x = -1450`), которую тоже надо отсечь.

## Как сделано вместо этого

[`layout.py`](maestro_parser/layout.py) сводит шум страницы к геометрии слотов:
отсекает всё за пределами листа, делит страницу на два ряда, в каждом ряду
берёт самый крупный прямоугольник слева (вид снаружи) и справа (вид внутри),
и поглощает накладную графику, которая лежит внутри них.

[`image_extractor.py`](maestro_parser/image_extractor.py) **растрирует страницу**
через этот прямоугольник, а не достаёт объекты. PDF-рендерер сам собирает стопку —
полотно, маску и все накладки — ровно так, как это напечатано. Дальше:

- рендер с восьмикратным суперсэмплингом, чтобы векторные накладки не лесенкой;
- сведение на белую подложку (часть дверей с маской, часть — непрозрачный JPEG
  уже на белом; вытравливать фон значило бы получить ореол у одних и испортить
  другие, у которых панель внутри белая);
- оба вида центрируются на **общем холсте**, высота которого задана видом
  снаружи, — за счёт этого масштаб у двух видов одинаковый и в карточке дверь
  при переключении не «прыгает»;
- Lanczos-даунсэмплинг до двух размеров (`full` 1200 px, `card` 640 px) и лёгкий
  unsharp, компенсирующий мягкость ресэмплинга;
- экспорт в WebP.

Исходная графика внутри PDF — примерно 309×640 px, поэтому 1200 px по высоте
это потолок осмысленного: дальше растёт вес, а не детализация.

## Разбор текста

[`text_parser.py`](maestro_parser/text_parser.py) классифицирует строки
по кеглю, начертанию, цвету и координатам, а не по порядку чтения. Два места,
где это было неочевидно:

- **Строки, а не блоки.** На нескольких страницах PyMuPDF склеивает заголовок
  модели (левое поле) и колонку характеристик в один блок. Фильтр по
  `x` на уровне блока молча съедал всю спецификацию — фильтровать нужно строки.
- **Метки, а не жирность.** Начертание в каталоге не выдержано: на страницах
  с терморазрывом `Порошковое покрытие:` набрано светлым. Поэтому строка
  считается новой характеристикой, если её начало совпадает с меткой
  из закрытого словаря `SPEC_LABELS`, а не потому, что она полужирная.

Граница между рядами (`row_split_y = 456`) измерена по каталогу: тело верхнего
ряда заканчивается на `y = 448`, первый элемент нижнего начинается на `y = 464.4`.
Деление по середине страницы разрезало бы хвост абзаца «Нестандарт».

## Формат датасета

```jsonc
{
  "source": "Каталог MaestroDoors ИЮЛЬ.pdf",
  "generatedAt": "2026-08-13T…",
  "cover": "/doors/cover.webp",
  "collections": [
    { "id": "met-mdf-60", "title": "6 см · МЕТ/МДФ", "description": "…", "count": 3 }
  ],
  "doors": [
    {
      "id": "mst-1",
      "title": "МЕЛАМИН",
      "article": "МСТ-1",
      "series": "6,0 см",
      "collectionId": "met-mdf-60",
      "page": 2,
      "badges": ["В наличии"],
      "description": "…",
      "images": {
        "front": "/doors/mst-1-front.webp",
        "back": "/doors/mst-1-back.webp",
        "frontCard": "/doors/mst-1-front-card.webp",
        "backCard": "/doors/mst-1-back-card.webp"
      },
      "specs": {
        "material": "Толщина 60мм / с МДФ 60мм",
        "finish": "Атмосферостойкое. Цвет - \"Антик медь\"",
        "interior": "Эконом панель 6 мм. Цвет - \"Венге светлый\"",
        "sealing": "2 контура",
        "dimensions": ["860 × 2050 мм", "960 × 2050 мм"]
      },
      "specList": [{ "label": "Дверная коробка", "value": "Короб открытый." }],
      "customSizes": "Возможно изготовление по спец заказам, …"
    }
  ]
}
```

`specs` — сжатая выжимка для карточки и шапки модального окна, `specList` —
полная спецификация в порядке каталога.

Структура повторяет типы в
`frontend/src/entities/door/model/types.ts` — менять нужно оба места.

## Правки под новый каталог

Если вёрстка сменится, почти всё настраивается в [`config.py`](maestro_parser/config.py):

| Что | Где |
|---|---|
| Диапазон товарных страниц | `LayoutConfig.first_product_page` / `last_product_page` |
| Граница рядов и колонок | `LayoutConfig.row_split_y` / `view_split_x` |
| Размеры и качество экспорта | `RenderConfig.variants` |
| Словарь характеристик | `SPEC_LABELS` |
| Названия коллекций | `COLLECTION_OVERRIDES` |
| Статусы | `BADGE_LABELS` |

Колонтитулы набраны вручную и содержат производственные пометки (один читается
`85 мдф мдф ДВЕРИ 2 КОНТУРА МДФ/МДФ…`), поэтому коллекции сопоставляются
таблицей, а не парсятся.
