# Бэкенд: приём заявок

Небольшой сервер на Express, который принимает форму «Оставить заявку» и
отправляет её письмом по SMTP.

```bash
npm install
cp .env.example .env      # Windows: copy .env.example .env
# заполните SMTP_USER и SMTP_PASS
npm run check-smtp        # проверить настройки, ничего не отправляя
npm run dev               # http://localhost:3001
```

## Что нужно заполнить в `.env`

| Переменная | Что это | Значение по умолчанию |
|---|---|---|
| `SMTP_HOST` | Адрес почтового сервера | `smtp.gmail.com` |
| `SMTP_PORT` | Порт | `465` |
| `SMTP_SECURE` | `true` для 465 (SSL), `false` для 587 | выводится из порта |
| **`SMTP_USER`** | **Полный адрес ящика-отправителя** | — **заполнить** |
| **`SMTP_PASS`** | **Пароль приложения (не пароль от аккаунта)** | — **заполнить** |
| `RECIPIENT_EMAIL` | Куда приходят заявки | `andrey.ves@yandex.ru` |
| `SEND_COPY_TO_SENDER` | Копия в ящик отправителя | `true` |
| `MAIL_FROM_NAME` | Имя в поле «От кого» | `Сайт ООО СК «Пирс»` |
| `PORT` | Порт сервера | `3001` |
| `ALLOWED_ORIGINS` | Домены фронтенда через запятую | пусто = любой |
| `RATE_LIMIT_WINDOW_MS` / `RATE_LIMIT_MAX` | Окно и лимит отправок с одного адреса | 10 мин / 5 |

`.env` в git не попадает — он в `.gitignore`. В репозитории лежит только
шаблон `.env.example`.

## Пароль приложения Gmail

Обычный пароль от аккаунта Google для SMTP **не подойдёт** — сторонним
программам нужен отдельный 16-символьный пароль приложения.

1. Включите двухэтапную аутентификацию: <https://myaccount.google.com/security>
   → «Вход в аккаунт Google» → «Двухэтапная аутентификация». Без неё пункт
   с паролями приложений не появится.
2. Откройте <https://myaccount.google.com/apppasswords>
   (или: Аккаунт Google → Безопасность → Двухэтапная аутентификация →
   в самом низу «Пароли приложений»).
3. Введите название, например `Сайт СК Пирс`, и нажмите «Создать».
4. Google покажет 16 символов четвёрками — `abcd efgh ijkl mnop`.
   Скопируйте их в `SMTP_PASS`; пробелы можно оставить, они игнорируются.
   **Пароль показывается один раз** — потерялся, создайте новый и удалите старый.
5. В `SMTP_USER` укажите полный адрес этого же ящика.

Если пункта «Пароли приложений» нет: чаще всего не включена двухэтапная
аутентификация, либо это корпоративный аккаунт Google Workspace, где
администратор запретил их выдачу.

Для других провайдеров логика та же:

- **Яндекс** — Почта → Все настройки → Безопасность → «Пароли приложений»,
  хост `smtp.yandex.ru`, порт `465`.
- **Mail.ru** — Настройки → Безопасность → «Пароли для внешних приложений»,
  хост `smtp.mail.ru`, порт `465`.

## Проверка

```bash
npm run check-smtp
```

Проверяет соединение и авторизацию, ничего не отправляя. Чтобы прислать
тестовую заявку на `RECIPIENT_EMAIL`:

```bash
npm run check-smtp -- --send
```

## API

### `POST /api/leads`

```jsonc
// запрос
{
  "name": "Иван",
  "phone": "+79001234567",
  "door": "СБ-ЛАЙН-3 (МД-10), 9,5 см",
  "comment": "Проём 900×2050",   // необязательно
  "website": ""                   // ловушка для ботов, должно быть пустым
}
```

| Ответ | Когда |
|---|---|
| `200 {"ok":true}` | Письмо отправлено |
| `400 {"ok":false,"errors":{...}}` | Не прошло проверку; `errors` — по полям |
| `429 {"ok":false,"message":"..."}` | Превышен лимит отправок |
| `502 {"ok":false,"message":"..."}` | SMTP недоступен или отклонил письмо |

### `GET /api/health`

```json
{ "ok": true, "service": "leads", "time": "2026-08-15T13:43:33.002Z" }
```

## Как это устроено

| Файл | Отвечает за |
|---|---|
| `config.ts` | Чтение и проверка переменных окружения; падает на старте, если чего-то нет |
| `validation.ts` | Проверка заявки на сервере и нормализация телефона |
| `mailer.ts` | SMTP-транспорт и вёрстка письма |
| `rateLimit.ts` | Ограничение частоты |
| `routes/leads.ts` | Обработчик `POST /api/leads` |
| `index.ts` | Сборка приложения и запуск |

Пара решений, которые стоит знать.

**Валидация продублирована на клиенте и на сервере.** Клиентская — ради
удобства: человек видит опечатку сразу. Серверная — потому что запрос можно
отправить в обход формы.

**Квоту расходует только состоявшаяся отправка.** Счётчиков два: строгий на
письма и свободный (в 8 раз выше) на общий поток запросов. Если считать все
запросы подряд, клиент, дважды ошибившийся в номере телефона, исчерпает лимит
на ошибках валидации и не сможет отправить исправленную заявку.

**Ловушка для ботов отвечает «успешно».** Поле `website` скрыто от людей, но
автозаполнялки его находят. Заполненное поле — признак робота: сервер молча
отбрасывает заявку и отвечает `200`. Честная ошибка только подсказала бы,
какое поле обходить.

**Счётчики живут в памяти процесса.** Этого достаточно для одного инстанса.
Если приложение поедет в несколько реплик, счётчики нужно вынести в общее
хранилище.

## Развёртывание

Сервер нужен там, где можно выполнять код: VPS, Timeweb, Render, Railway,
Amvera и подобные. **GitHub Pages не подойдёт — там только статика.**

```bash
npm ci --omit=dev
npm run build
npm start
```

Переменные окружения задайте средствами хостинга (файл `.env` на прод обычно
не кладут). В `ALLOWED_ORIGINS` перечислите домены, откуда открывается сайт,
чтобы форму не дёргали с чужих страниц.

Фронтенд при сборке должен знать адрес этого сервера:

```bash
VITE_API_URL=https://адрес-бэкенда npm run build --prefix frontend
```
