# Витрина каталога

React 19 + TypeScript + Vite. Архитектура — [Feature-Sliced Design](https://feature-sliced.design/).

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # прод-сборка в dist/
npm run typecheck
npm run lint
```

Публикация на сервер — командой `deploy/deploy.ps1` из корня проекта,
см. [DEPLOY.md](../DEPLOY.md).

> Перед первым запуском соберите данные: `python ../parser/run.py`.
> Папка `public/doors/` — выгрузка парсера, в git не хранится.

## Архитектура

Слои, сверху вниз. Импорты идут **только вниз**; это проверяется ESLint'ом
(`no-restricted-imports` в [`eslint.config.js`](eslint.config.js)), поэтому
нарушение падает на `npm run lint`, а не всплывает через полгода.

```
app        точка входа, глобальные стили и токены
  ▼
pages      catalog — единственная страница
  ▼
widgets    site-header · hero · catalog-grid · door-details-modal · site-footer
  ▼
features   door-view-toggle · filter-doors · request-quote
  ▼
entities   door — типы, селекторы, доступ к данным, DoorCard/DoorImage/DoorSpecList
  ▼
shared     ui-кит, хелперы, конфиг, сгенерированный датасет
```

`app` и `shared` — плоские: внутри них сосед соседа импортировать можно
(`shared/ui` законно пользуется `shared/lib`). Слайсы промежуточных слоёв
независимы друг от друга.

### Где что лежит

| Компонент | Слой | Файл |
|---|---|---|
| `Grid` | widget | `widgets/catalog-grid/ui/CatalogGrid.tsx` |
| `Card` | entity | `entities/door/ui/DoorCard/DoorCard.tsx` |
| `ImageToggle` | feature | `features/door-view-toggle/ui/ImageToggle.tsx` |
| `Modal` | shared + widget | `shared/ui/Modal` (примитив) + `widgets/door-details-modal` |
| `CTAButton` | feature | `features/request-quote/ui/CTAButton.tsx` |
| Форма заявки | feature | `features/request-quote/ui/RequestQuoteModal.tsx` |
| `doorsData` | entity | `entities/door/api/catalogApi.ts` |
| Реквизиты и контакты | shared | `shared/config/site.ts` |

### Пара решений, которые стоит знать

**Карточка не импортирует переключатель.** `ImageToggle` — это feature, а
features лежат выше entities. Поэтому `DoorCard` принимает его пропом
`viewToggle`, а собирает их вместе виджет `CatalogGrid`.

**Состояние вида — у каждой карточки своё.** `useDoorView` вызывается внутри
`CatalogGridItem`, а не в цикле по дверям: перевернуть одну плитку и не тронуть
остальные иначе не выйдет, да и хуки в `map` вызывать нельзя.

**Оба вида смонтированы всегда.** `DoorImage` держит в DOM обе картинки и
переключает их прозрачностью — переворот мгновенный после первой загрузки и
не мигает пустой рамкой.

**Кадр двери — не 1:2.** Отрисованная картинка вертикальная, но сетка таких
плиток невыносима при прокрутке. Рамка задаётся переменной `--door-frame`
(в сетке 1:1.55, в модалке 1:1.9), картинка вписывается через `object-fit:
contain`, а белая подложка превращает остаток ширины в поля.

**Базовый путь подставляется ровно в одном месте.** В датасете лежат
относительные пути (`doors/...`), а префикс сборки добавляется в
`entities/door/api/catalogApi.ts` при загрузке. Сейчас `base` равен `'/'`,
но если сайт когда-нибудь поедет в подкаталог домена — достаточно поменять
его в `vite.config.ts`. Дублировать преобразование в селекторах или
компонентах нельзя: префикс применится дважды, получится
`/base/base/doors/...`, и все картинки отдадут 404.

**Форма заявки — одна на весь сайт.** `RequestQuoteModal` живёт на уровне
страницы и открывается из трёх мест: шапки, подвала и карточки модели. Из
карточки поле «Дверь» приходит заполненным, но остаётся редактируемым.

## Дизайн

Палитра снята с печатного каталога: `#fdb21e` (акцент), `#2b2a29` (текст),
`#5b5b5b` (заголовки), `#e5e5e5` (линии). Токены — в
[`app/styles/tokens.css`](src/app/styles/tokens.css). Шрифт — Jost.

Сетка: **4 колонки** на десктопе → 3 (≤1279px) → 2 (≤899px) → 1 (≤519px).

Логотип (`public/logo.png`) идёт с собственной непрозрачной подложкой, поэтому
показывается плиткой: вытравить фон нельзя — по краям букв останется ореол.

## Отправка заявок

Форма шлёт `POST /api/leads` на тот же адрес, откуда открыт сайт:

- **в разработке** запрос уходит на `/api`, а Vite проксирует его на
  `http://localhost:3001` (см. `vite.config.ts`);
- **на сервере** сайт и API отдаёт один процесс, поэтому запрос попадает
  куда надо сам — настраивать ничего не нужно.

Переменная `VITE_API_URL` (шаблон — в [`.env.example`](.env.example)) нужна
только в одном случае: если фронтенд вынесут на отдельный домен. Тогда в ней
указывают адрес бэкенда, а в `ALLOWED_ORIGINS` на сервере — адрес фронтенда.

Без запущенного бэкенда сайт работает, но форма покажет ошибку связи.
Описание API — в [`backend/README.md`](../backend/README.md#api).

## Доступность

- модальные окна — `role="dialog"`, фокус входит при открытии и возвращается
  на карточку при закрытии, Tab заперт внутри, Escape и клик по фону закрывают;
  форма заявки открывается поверх карточки модели отдельным слоем;
- поля формы связаны с сообщениями об ошибках через `aria-describedby`;
- переключатель вида — `radiogroup`, работает с клавиатуры, в галерее модалки
  вид переключается стрелками ←/→;
- фильтр коллекций — `tablist`, управляющий сеткой;
- вся плитка кликабельна, но клик обрабатывает настоящая `button` внутри;
- `prefers-reduced-motion` отключает анимации.
